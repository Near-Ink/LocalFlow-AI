LocalFlow AI · 开发者功能文档

对外 OpenAI 兼容 API 使用说明

把 LocalFlow 的本地 / 云端模型暴露成标准 OpenAI 接口，供任何第三方 Agent、脚本与工具直接调用。
协议：OpenAI Chat Completions 默认地址：http://127.0.0.1:8765/v1 鉴权：Bearer API Key 支持流式 支持多模态

1. 它能做什么

在本机启动 LocalFlow 后，它既是聊天应用，也是一个 推理服务。把它暴露的 /v1 地址当成任何云厂商的 OpenAI 兼容入口即可——本机的 llama3.1、 qwen2.5vl 等本地模型，以及你绑定的云端模型，都能被统一的 chat/completions 协议调用，而无需关心底层用的是 Ollama 还是云端 API。

适用于：Dify、n8n、FastGPT 等填写「自定义模型 / OpenAI 兼容」接入点；自研脚本； 其它 Agent 框架接入本地便宜、私密的推理能力。

2. 快速开始（三步）

1

重启正式后端并配置密钥

在系统终端重启用带 LOCALFLOW_API_KEY 的命令（把密钥换成你自己的）：

kill "$(lsof -t -iTCP:8765 -sTCP:LISTEN)" && cd "/Users/zhanghaoran/Documents/LocalFlow AI/backend" && \
LOCALFLOW_API_KEY=你的密钥 nohup ./start_localflow.sh &

本机 Ollama 需在运行。不设置该环境变量则本机免鉴权（仅本机建议设置，见「安全」）。

2

确认端点在线

curl http://127.0.0.1:8765/api/health
# {"status":"ok","version":"0.1.0","app":"LocalFlow AI"}
3

在客户端填入三项配置

base_url  =  http://127.0.0.1:8765/v1
api_key   =  你的密钥
model    =  llama3.1:8b（或用 GET /v1/models 查看全部）

3. 端点

方法 & 路径说明
GET /v1/models列出可用模型（本机 Ollama + 云端绑定模型）
POST /v1/chat/completions对话补全；stream=true 时返回 SSE 流

4. 鉴权

当后端以 LOCALFLOW_API_KEY 启动时，所有请求须携带 Bearer Token：

Authorization: Bearer 你的密钥
  • 缺省 / 错误密钥 → 401 Unauthorized
  • 未配置密钥启动 → 本机免鉴权（方便起见，但建议始终设置）

5. 请求示例

cURL · 非流式

curl http://127.0.0.1:8765/v1/chat/completions \
  -H "Authorization: Bearer 你的密钥" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "llama3.1:8b",
    "messages": [
      {"role": "user", "content": "用一句话介绍你自己"}
    ],
    "temperature": 0.7
  }'

cURL · 流式

curl http://127.0.0.1:8765/v1/chat/completions \
  -H "Authorization: Bearer 你的密钥" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "llama3.1:8b",
    "messages": [
      {"role": "user", "content": "打个招呼"}
    ],
    "stream": true
  }'

Python · openai SDK

from openai import OpenAI

client = OpenAI(
    api_key="你的密钥",
    base_url="http://127.0.0.1:8765/v1",
)

resp = client.chat.completions.create(
    model="llama3.1:8b",
    messages=[{"role": "user", "content": "为什么天空是蓝的？"}],
)
print(resp.choices[0].message.content)

其他 Agent / 低代码平台接入

  • Dify：设置 → 模型供应商 → 「自定义/OpenAI API」→ 填以上 base_url、api_key、model。
  • n8n：添加「OpenAI」节点 → 使用自定义 base URL 指向本地址。
  • 任何 OpenAI SDK：仅需 base_url 覆盖，其余用法完全相同。

6. 消息与多模态

messages 兼容 OpenAI 结构，支持 system / user / assistant 角色。 对于视觉模型，content 可传 parts 数组并附带 base64 图片：

{
  "model": "qwen2.5vl:7b",
  "messages": [{
    "role": "user",
    "content": [
      {"type": "text", "text": "这张图里是什么颜色？"},
      {"type": "image_url", "image_url": {
        "url": "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA..."
      }}
    ]
  }]
}

图片请以 data: URL（base64）形式传入；纯文本字符串直接传入即可。

7. 模型路由规则

请求的 model路由到
云端绑定的模型名云端引擎（OpenAI 兼容服务）
本机 Ollama 已安装的模型名本地引擎（Ollama）
省略 / 空配置的默认模型 default_model
其它未知名称404，并提示查看 /v1/models

8. 响应结构（非流式）

{
  "id": "chatcmpl-...", "object": "chat.completion", "created": 1787989895,
  "model": "llama3.1:8b",
  "choices": [{
    "index": 0,
    "message": {"role": "assistant", "content": "你好"},
    "finish_reason": "stop"
  }],
  "usage": {"prompt_tokens": 17, "completion_tokens": 3, "total_tokens": 20}
}

流式响应为 SSE：每行 data: {json}，字段为 choices[].delta.content 逐字增量，结束时输出 finish_reason 与 usage，并以 data: [DONE] 收尾。

✓ 常见正常情况
  • 返回 200，含 choices 与 usage
  • 流式逐块返回，最后 [DONE]
常见错误
  • 401 缺密钥或密钥错误
  • 400 messages 为空 / 模型调用失败
  • 404 模型不存在，看 /v1/models

9. 安全提醒

  • 默认后端只监听 127.0.0.1，仅本机进程可访问——别改为 0.0.0.0 或做公网映射，除非你确认网络环境安全。
  • 强烈建议始终设置 LOCALFLOW_API_KEY，防止本机其它网页脚本偷偷调用你的模型。
  • 密钥对待，别写进共享代码或提交到仓库。
